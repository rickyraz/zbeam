# Protocol Source Matrix

This matrix is the normative source index for implementation work. Project specifications explain design intent; official Erlang/OTP documentation defines wire compatibility.

## Initial implementation subset

### ETF

- version byte `131`;
- `SMALL_INTEGER_EXT`, `INTEGER_EXT`;
- `SMALL_ATOM_UTF8_EXT`, `ATOM_UTF8_EXT`;
- `SMALL_TUPLE_EXT`, `LARGE_TUPLE_EXT`;
- `NIL_EXT`, `STRING_EXT`, `LIST_EXT`, `BINARY_EXT`;
- `NEW_PID_EXT`.

### EPMD

- `ALIVE2_REQ` / `ALIVE2_RESP` and `ALIVE2_X_RESP`;
- `PORT_PLEASE2_REQ` / `PORT2_RESP`.

### Handshake

- OTP 23+ name/challenge format;
- status exchange;
- MD5 cookie challenge digest as required by the distribution handshake;
- explicit initiating and accepting state machines.

### Connected distribution

- four-byte packet framing and tick packets;
- pass-through distribution header;
- `REG_SEND` and `SEND` control operations for the first echo path.

## MVP audit update — 2026-09-26

- `PORT2_RESP` error is exactly `[119, Result]` when Result is nonzero. The client reads those two bytes before attempting success-only fields. The byte-level regression is exercised through a deterministic socket peer.
- Handshake and distribution have different length prefixes. Handshake readers must not prefetch distribution bytes and discard them at API handoff; the coalesced-frame tests cover both roles.
- `REG_SEND` validates the four-element control tuple, sender PID, legacy cookie atom and registered-name atom. Unknown destinations do not trigger payload decoding.
- Optional `DFLAG_DIST_MONITOR`, `DFLAG_DIST_HDR_ATOM_CACHE` and `DFLAG_FRAGMENTS` remain clear. OTP's mandatory baseline flags are necessary for connection establishment but exceed current payload-tag coverage; this is a restricted profile, not full flag-semantic conformance.
- The target OTP 25/26/27 black-box suite now verifies both handshake roles, repeated supported values, idle ticks, rejected cookies, reconnect and process loss. The shared local EPMD daemon version is recorded with the evidence.

Current scope and remaining gaps are specified in [mvp.md](mvp.md), with [Phase B results](evidence/phase-b/2026-09-26-mvp.md).

## Worker monitor audit — 2026-10-25

The additive `serve-worker` profile enables both `DFLAG_DIST_MONITOR` and
`DFLAG_DIST_MONITOR_NAME`. In OTP 27's
[`dist.c`](https://github.com/erlang/otp/blob/OTP-27.3.4.19/erts/emulator/beam/dist.c),
`erts_dsig_send_monitor`, `erts_dsig_send_demonitor` and `erts_dsig_send_m_exit`
check `~ctx->dflags & (DFLAG_DIST_MONITOR | DFLAG_DIST_MONITOR_NAME)` and reduce
missing-bit monitoring to connection supervision. PID-only negotiation therefore
does not meet the process-monitor contract. This is tested against actual
OTP 25/26/27, not treated as a private flag reinterpretation.

Controls 19/20 take a PID watcher and PID/atom target; control 21 reverses those
positions and appends a reason. The only registered service name is
`zbeam_worker`; named monitoring follows that endpoint, not the worker PID it
returns. Optional payload-exit flags remain clear. Bounded references and the
[wire/runtime evidence](evidence/phase-b/2026-10-25-m1.md) extend, rather than
retroactively change, the historical MVP subset above.

## Fixture policy

`fixtures/etf/manifest.tsv` is generated from `:erlang.term_to_binary/1`. The manifest records the generator OTP version, source expression, and lowercase hexadecimal bytes. A fixture generated by OTP 28 may validate stable ETF tags, but it does not establish OTP 25–27 interoperability; target-version black-box tests remain required.
