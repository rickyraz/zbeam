# Fixed SHA-256 Worker — 2026-09-28

- Branch `feat/worker-lifecycle`; based on liveness commit `c47968d`.
- Zig 0.16.0, Linux x86-64/WSL2. Compatibility tests: pinned real OTP 25/26/27; benchmarks: local OTP 28, Elixir 1.19.5, two BEAM schedulers.
- Scope: one synchronous registered `sha256` service handling an ETF binary and replying with its 32-byte digest. It uses existing REG_SEND/SEND and the existing ETF binary/frame bounds; it does not add a general actor scheduler, RPC or monitor/link controls.

`zbeam sha256 NAME COOKIE [COUNT]` serves one peer; `serve-sha256` serves sequential peers. `examples/sha256_worker.exs` launches the native worker, sends one bounded file, monitors node loss and checks the exact digest against BEAM crypto. The example was run against `README.md`. It does not supervise or automatically restart the worker; argv cookies and loopback-only listening remain development-only.

The Port reference accepts an optional `sha256` job and returns the same 32-byte digest for the same input. The benchmark's expected digest is computed **before** its timed loop. The default echo job and its 2026-09-26 evidence are preserved. Unit tests cover a known SHA-256 vector, recipient PID, nonbinary rejection, unknown-route discard and the configured ETF binary limit. The OTP matrix checks empty, three-byte and 64 KiB binaries, unsupported matching input disconnect, and reconnect across OTP 25/26/27; the original echo handshake roles still pass.

## Repeated Port comparison

Run 500 sequential requests after warm-up, with five independent process launches for each job and payload size. One launch benchmarks Port first, then distribution; run order is fixed, not randomized. The output for the SHA-256 job is a 32-byte digest on both paths. Throughput includes BEAM harness time; handshake, startup, restart and the BEAM expected-digest calculation are outside timed steady-state samples.

| Job | Input | Path | Median-of-five p50 | Median-of-five p95 | Median throughput |
|---|---:|---|---:|---:|---:|
| echo | 32 B | Port | 97.678 µs | 145.884 µs | 9,755.4/s |
| echo | 32 B | distribution | 825.290 µs | 1,099.071 µs | 1,164.2/s |
| SHA-256 | 32 B | Port | 100.290 µs | 146.903 µs | 9,675.1/s |
| SHA-256 | 32 B | distribution | 866.746 µs | 1,070.471 µs | 1,120.3/s |
| echo | 64 KiB | Port | 399.415 µs | 529.379 µs | 2,359.6/s |
| echo | 64 KiB | distribution | 2,179.072 µs | 2,632.770 µs | 445.4/s |
| SHA-256 | 64 KiB | Port | 367.211 µs | 486.661 µs | 2,531.6/s |
| SHA-256 | 64 KiB | distribution | 1,597.255 µs | 1,895.404 µs | 613.6/s |

**Port wins in all four paired comparisons on this host.** The different echo and SHA-256 response sizes make cross-job latency comparisons invalid as an allocator or hashing-cost attribution. Reliability timers now create concurrent tasks for I/O waits; no CPU/syscall profile or matched before/after experiment establishes how much of the network time they consume. There is no native Linux host repeat outside WSL2, randomized ordering, confidence interval, loaded BEAM control or broader-job performance claim.

Artifacts: [environment/source/binary hashes](2026-09-28-sha256/environment.txt), [example SHA-256 64 KiB summary](2026-09-28-sha256/1-sha256-65536.summary.tsv), [its raw 1,000 Port/distribution latencies](2026-09-28-sha256/1-sha256-65536.raw.tsv), and all [20 runs with raw samples](2026-09-28-sha256/). Every percentile row was independently recomputed from all **20,000 raw samples** before the record was written. Per-run output is retained, including p99, RSS/HWM, whole-BEAM memory and one restart sample.

Reproduction:

```sh
zig build -j2 -Doptimize=ReleaseSafe
epmd -daemon
for repeat in 1 2 3 4 5; do
  for job in echo sha256; do
    for size in 32 65536; do
      ZBEAM_BENCH_JOB="$job" ZBEAM_BENCH_PAYLOAD_BYTES="$size" \
        ZBEAM_BENCH_SAMPLES="/tmp/$repeat-$job-$size.raw.tsv" ERL_FLAGS='+S 2:2' \
        ./scripts/bench_port_vs_zbeam.sh 500 > "/tmp/$repeat-$job-$size.summary.tsv"
    done
  done
done
```

This is a concrete worker/use-case check, not the supported-release example: external restart supervision, PID-directed multi-actor routing, process-monitor/link semantics and production secret handling remain unresolved.
