## W0 — Integrated reliability baseline

Integration branch: `feat/monitorable-worker`, starting at lifecycle plan
`4aa7333` on `master` `11c3319`. The merge imports only the shared foundation
through `38caeb4`: handshake deadlines (`7b812d3`), bounded frame/write waits and
EPMD fail-stop (`c47968d`), and the SHA-256 service (`38caeb4`). Existing historical
SHA-256 comparison artifacts remain historical; no performance experiment or
other research-branch tip is promoted.

Execution: 2026-10-25, Linux x86-64 WSL2, explicit Zig 0.16.0 executable from
`~/.vscode-server/data/User/globalStorage/ziglang.vscode-zig/zig/x86_64-linux-0.16.0/`.
The shell default remains Zig 0.17.0 and was not changed.

| Command (with Zig 0.16.0 first on PATH) | Result | Raw record |

| `timeout 240 zig build test-all -j2 --summary all` | Passed | [Debug](2026-10-25-m1/w0-debug.log) |

The integrated regression covers bad cookies, partial/silent handshakes, partial
frames, blocked replies, cancellation, positive-demand admission, next-peer
recovery and registration loss. A nonreturning CPU handler is not preempted.
Pausing demand also pauses ticks; a sufficiently long pause may disconnect the
peer. No speculative reads, hidden queue or unlimited-pause guarantee is added.

W0 is verified. Later M1 increments require their own tests; these results do not
establish process monitors, actor-local panic isolation or production deployment.

## W3 — Single-worker identity and correlated requests

`test-all` passed 62/62 in both [Debug](2026-10-25-m1/w3-debug.log) and
[ReleaseSafe](2026-10-25-m1/w3-release.log), using the same Zig 0.16.0 and host.
The [pinned OTP matrix](2026-10-25-m1/w3-otp.log) passed 25/26/27 for legacy
services and the new worker profile. Commands are W0's commands, rerun on W3.

The new smoke checks discovery, exact empty/3-byte/1-MiB hashes, bad-request
handling, a mutated stale PID, identity preservation on TCP reconnect and normal
stop with node survival. Unit tests sweep allocation failures through discovery,
hash, stop and reply decoding; fixed test output storage avoids conflating writer
allocation failure with codec allocation errors. Monitor flags are still off.

PID generation uses EPMD creation plus a random ID/serial. This is not an absolute
persistent identity guarantee after EPMD state loss. No native scheduler, queued
payload lifetime or automatic worker restart is inferred from these tests.

## W4 — Bounded PID and named process monitors

`test-all` passed 69/69 in [Debug](2026-10-25-m1/w4-debug.log) and
[ReleaseSafe](2026-10-25-m1/w4-release.log). The complete pinned OTP 25/26/27
matrix passed in [Debug](2026-10-25-m1/w4-otp-debug.log) and
[ReleaseSafe](2026-10-25-m1/w4-otp-release.log), including all prior service checks.
Commands are W0's commands, rerun on W4 in both optimization modes.

Black-box assertions cover exact `DOWN` reference/object/reason, unknown PID/name
`noproc`, demonitor/flush, `normal` worker exit with node/discovery survival,
connection-loss `noconnection`, stable PID after reconnect and no replay/duplicate.
Unit tests cover idempotence, conflicting reference reuse, canonical retained
slices, 64-slot exhaustion, failed stop output and exhaustive allocation failures
through subscribed stop/notifications. A positive demand credit gates all frames.

The original PID-only negotiation failed in real OTP; source inspection found
OTP requires both monitor flags. Named endpoint semantics were implemented and
the normative correction is recorded in superseding ADR 0003. ADR 0002's
original body is retained under the repository's immutable-ADR policy. No outbound subscription API, native
links, actor-local panic isolation or production security guarantee is established.

## W5 — External ownership, admission and recovery

Zig 0.16.0; Linux x86-64 WSL2; Python 3.14; Elixir 1.20.4 on OTP 29. The optional
launcher/example are not native runtime dependencies. Commands:

```sh
python3 tests/integration/worker_guard_test.py
zig build test-worker-recovery -j2 --summary all
zig build test-worker-recovery -j2 -Doptimize=ReleaseSafe --summary all
zig build test-all -j2 --summary all
zig build test-all -j2 -Doptimize=ReleaseSafe --summary all
zig build test-interop-docker -j2 -Doptimize=ReleaseSafe --summary all
```

[Guard checks](2026-10-25-m1/w5-guard.log) passed 20 repetitions of EOF, guardian
TERM/KILL and native exit. A procfs ESRCH race found during repetition is treated
as exited; unrelated I/O errors remain visible. The owner campaigns passed all
13 complementary ExUnit scenarios in [Debug](2026-10-25-m1/w5-recovery-debug.log)
and [ReleaseSafe](2026-10-25-m1/w5-recovery-release.log): 12 ordinary cases plus
one private-EPMD case, run in separate VMs. Their exclusions are complementary,
not skipped acceptance cases. Panic, allocation failure and spin each run twice.
The target also checks the finite runnable example's exact hashes.

Scenarios include failed readiness without terminate cleanup, busy/invalid input,
normal process exit, native/guardian/owner/controlling-VM SIGKILL, connection loss,
caller death during admission, restart intensity, request timeout and old-reference
rejection while replacement work is pending. Native/guardian PIDs are tracked
from owned Ports/procfs; bounded checks establish no owned live child after
cleanup. Linux init/service-manager reaping of abrupt-death zombies is a separate
host responsibility. Most campaigns also check an unrelated BEAM process and
unchanged VM identity. Private EPMD loss uses cancellable paused work; spin cannot
be preempted safely even by EPMD fail-stop and instead uses the owner deadline.

Final core regressions passed 69/69 in [Debug](2026-10-25-m1/w5-core-debug.log) and
[ReleaseSafe](2026-10-25-m1/w5-core-release.log). The final
[pinned OTP 25/26/27 regression](2026-10-25-m1/w5-otp-release.log) passed all legacy
and monitor-profile checks. This is separate from the OTP 29 Elixir-owner run.
No new benchmark, arbitrary-term compatibility or production safety claim is made.
