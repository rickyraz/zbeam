# External worker supervision and explicit uncertain-request failure

**Decision:** external supervision is viable for this restricted worker. It is not a latency advantage over Ports, automatic replay, or a production supervision library.

## Contract

The development `NativeWorkerOwner` GenServer owns one Port/connection and one active bounded binary request. It uses non-suspending transport submission so the owner can still process its timer. Concurrent admitted calls are rejected; callers must separately bound their own outstanding calls and BEAM mailboxes. A one-second request timeout destroys the old connection/process, preventing an uncorrelated late reply from being accepted as a later request. The external supervisor launches a fresh peer with a 100 ms restart delay and an intensity limit of three restarts per five seconds. A fresh successful request is explicit; failed work is never replayed.

Startup-only test faults are confined to the optional peer. Injected allocator failure is a failing allocator, not simulated global system-memory exhaustion. Spin is deliberately noncooperative native code; SIGKILL cleanup uses only the OS PID obtained from its owned Port. EPMD-loss trials use a private foreground daemon on a dedicated loopback port and never kill shared EPMD.

## Executed verification

On Zig 0.16.0/OTP 29/Elixir 1.20.4, four-CPU WSL2:

- ReleaseSafe `test-all build-research-peer`: **54/54 passed**; `zig build` installed the raw Port control.
- Owner contract self-check: payload bounds, overlap rejection, ordered digests, timeout termination and closed old Port passed.
- **60 restart trials:** ten each for native process SIGKILL, raw Port SIGKILL, injected panic, injected OOM, noncooperative spin and private EPMD loss.
- Every trial recorded an explicit `worker_lost`/`timeout` result for the uncertain request, restarted the owner/worker, verified a new digest, and checked unchanged BEAM OS PID plus unrelated-process response.

Raw results include request-to-failure, recovery, request-to-first-good-reply and BEAM-memory observations. Timing is a functional liveness observation, not a controlled throughput competition. An initial raw-Port run failed because its executable was not installed; `port-missing-binary-rejected.log` preserves that setup failure and is excluded from successful trials.

```sh
zig build -j2 -Doptimize=ReleaseSafe
zig build test-all build-research-peer -j2 -Doptimize=ReleaseSafe
ulimit -c 0
epmd -daemon
ERL_FLAGS='+S 2:2 +SDcpu 2 +SDio 1' elixir --name recovery@127.0.0.1 \
  --cookie research_cookie benchmarks/worker_recovery.exs \
  "$PWD/zig-out/bin/zbeam-research-peer" spin 10
python3 scripts/bench/private_epmd.py 10
```

Repeat the normal invocation for `kill`, `port_kill`, `panic`, `oom`; `worker_owner_test.exs` accepts the same executable without mode/count. Raw logs are under `2026-10-13-recovery/`. Fault commands may crash only their disposable native workers. The supervisor is caller-side example code and introduces no production battery dependency.

## Limits

Crash isolation is already provided by Ports. Caller flood admission, exactly-once/replay, persistent queues, process-wide memory exhaustion, startup-retry policies beyond the fixed example, native-host replication and loaded-BEAM fairness remain unverified. A fatal controlling-VM failure is outside the example's normal `terminate` cleanup contract; production process-tree cleanup needs independent supervision.
