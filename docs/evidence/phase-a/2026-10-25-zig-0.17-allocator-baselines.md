# Standard allocator baselines on Zig 0.17

Source: `explore/allocator-baselines` at `27b0fee`; canonical migration `ae7197d`.
This branch predates the NIF comparison and has no Zigler migration surface.
Linux x86-64 WSL2; existing application selector and battery DAG retained.

## Compiler and contract gates

- Explicit 0.16 `test-all test-allocators build-allocator-bench`: **36/36 steps,
  52/52 tests**.
- 0.17 `test-all test-labs test-allocators -j2`: **69/69 steps** in debug/safe,
  including both intentional compile failures.
- All five predeclared controls pass `test-allocators` in debug and safe:
  process-nolibc, smp-nolibc, debug-libc, smp-libc, libc. Each selector checks
  over-aligned realloc/data preservation, all-failure cleanup, cross-OS-thread
  bounded handoff/joining, procfs streaming and sample calculations.
- All five safe variants install their three binaries into distinct prefixes;
  compiler/startup-source and per-variant binary/linkage/symbol provenance is
  recorded. No rebuild occurs during a later matrix run.
- Pinned OTP 25/26/27 safe: **8/8 steps**. The existing profile remains restricted
  echo MVP, not the reliability/SHA-256 or M1 profiles.
- The third runnable target, `bench-allocators`, now uses `addPassthruArgs` and
  has its own invalid-workload forwarding assertion in `build_args_smoke.sh`.
  All three runnable-step checks, Zig/shell formatting and CI YAML checks pass.

Raw logs are `2026-10-25-zig-0.17/allocator-baselines-*.log.gz`.

## Provenance is not an allocator optimization

0.17 startup uses `SafeAllocator` for debug/safe even when libc is linked.
The explicit `debug` control intentionally retains the still-supported deprecated
`DebugAllocator` and its `.ok` teardown assertion. A real preflight confirms that
it still compiles/tests; it was not speculatively replaced with a different
comparator. Future API removal is recorded as research debt.

No default application choice changes, and no allocator shim or battery import
is added. Old 0.16 records retain their labels and results. The fresh matrix smoke at clean commit `d5c240f` passed **45 serial launches**:
five safe variants × three payload sizes × echo/handoff/network, one repetition,
three operations per cycle/implementation. `allocator_matrix.py` reproduced every
reported percentile from raw samples and wrote COMPLETE. A new source/binary/
compiler manifest, raw samples and commands are preserved in
`2026-10-25-zig-0.17/allocator-baselines-matrix.tar.gz`. This is a correctness smoke,
not the predeclared five-repeat performance campaign or a promotion decision.
