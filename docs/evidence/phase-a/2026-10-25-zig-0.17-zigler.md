# Pinned Zigler integration for Zig 0.17

**Scope:** optional native-comparison dependency only, after native compiler unit
`b270f0c`; no runtime battery dependency or production NIF safety claim.
**Environment:** Linux x86-64 WSL2, Zig 0.17.0, Elixir 1.20.4 / OTP 29.1.1.

## Why a dependency change is required

A fresh Zigler 0.16/Zig 0.16 baseline passes two eligible ExUnit cases. The same
pinned library with explicit Zig 0.17 fails at removed `std.Build.args` in its
generated build script. This is preserved in the preceding native-comparison
record; simply changing zbeam's build script cannot fix that dependency.

The [Hex API](https://hex.pm/api/packages/zigler) still reports 0.16.0 as the
latest published Zigler. The upstream 0.17 source is pinned, not followed as a
moving branch:

| Source | Exact commit / version |
|---|---|
| `E-xyza/zigler` | `feb80162d597ede227e9d4d5c9798a42beee9695` |
| `ziglang/translate-c` | `cfac21f3199b2b02ce3fd7db652aa456421fe4ab` |
| `ziglang/arocc` | `d0c8c4d9c55daa7ef6e40cf0f630a5b5e900989b` |
| Hex helpers | zig_get 0.17.0; zig_parser/zig_doc 0.8.0; other package versions retained |

All are locked in `benchmarks/zigler/mix.lock`. The project minimum is now
Elixir 1.18, matching upstream. No dependency source was patched locally.

## Verification and reproducibility

`mix test` passes in three fresh VMs using the final lock: **3 passed, 1 excluded**
in each VM. Normal and dirty CPU adapters return exact echo/SHA-256 results,
reject oversized input and reject malformed scalars/non-byte-aligned bitstrings.
The tests require a controlled BEAM error, not a dependency-specific exception
class: the bitstring case is an `ErlangError`, while scalar cases can be
`ArgumentError`. No successful malformed result or VM crash is accepted.

Each command explicitly sets `ZIG_EXECUTABLE_PATH` to the installed 0.17 binary,
unsets `ZIG_ARCHIVE_PATH`, and separates Zigler staging/cache from the old 0.16
baseline. `MIX_DEPS_PATH=/tmp/zbeam-017-rollout/deps-017` keeps fetched sources
separate from the old dependencies; normal users can use default `deps` as shown
in the README. The final NIF uses the normal `_build/test` path.

Compressed raw logs are `2026-10-25-zig-0.17/zigler-baseline-{deps-017*,nif-017*}.log.gz`.
`nif-017-final{1,2,3}` are the passing gates. Earlier dependency-fetch and overly
narrow exception-class attempts are retained, not counted as passing gates.
The provenance log records the compiler, lock, NIF and native-worker hashes and
all three Git dependency SHAs. Mix formatting and CI YAML assertions pass.
CI now exposes native/research and eligible NIF checks; GitHub execution itself
has not been observed locally.

Threaded adapters remain excluded and unscored after the historical segfault;
compiling newer upstream code does not clear that quarantine. This verifies this
small adapter surface, not the whole upstream library or production deployment.
No historical 0.16 measurements are changed, and no 0.17 performance claim follows.

A follow-on correctness matrix at clean commit `d2dfb9a` passes **20 fresh-VM
launches**: five eligible adapters × echo/SHA-256 × 32/4096-byte inputs, one
repetition and three checked samples per launch. Its source/binary/lock manifest,
raw samples and COMPLETE marker are in `2026-10-25-zig-0.17/zigler-baseline-smoke.tar.gz`.
This tiny smoke is not a latency/throughput measurement campaign or a score.
