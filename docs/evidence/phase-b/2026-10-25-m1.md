# M1 wire evidence

## W2 — Reference codecs and pure monitor controls

Zig 0.16.0, Linux x86-64 WSL2. Both `zig build test-all -j2 --summary all` and
`zig build test-all -j2 -Doptimize=ReleaseSafe --summary all` passed 59/59 tests.
Raw [Debug](../phase-c/2026-10-25-m1/w2-debug.log) and
[ReleaseSafe](../phase-c/2026-10-25-m1/w2-release.log) records include conformance,
integration and stress. Monitor capability is not enabled by this increment.

The OTP 27 distribution/ETF definitions indexed in `docs/protocol-sources.md`
were read on 2026-10-25. PID monitor controls are 19/20/21; named monitors,
SEND_SENDER and payload-exit controls are distinct capabilities and remain off.
NEWER_REFERENCE_EXT has a two-byte word count, atom node, four-byte creation and
up to five opaque 32-bit words. Legacy NEW_REFERENCE_EXT has one-byte creation
(two significant bits), a first word limited to 18 bits, and at most three words.
The supported profile rejects zero-word references and emits only newer form.

[Reference-vector output](2026-10-25-m1/reference-vectors.log) records actual
pinned Docker OTP 25/26/27, using the existing matrix image digests. In each VM:

```erlang
lists:foreach(fun({N,B}) ->
  R = binary_to_term(B),
  io:format("ref~p ~s~n", [N, binary:encode_hex(term_to_binary(R,[{minor_version,2}]))])
end, [
 {1, <<131,90,0,1,119,3,"n@h",7:32,1:32>>},
 {3, <<131,90,0,3,119,3,"n@h",7:32,1:32,2:32,3:32>>},
 {5, <<131,90,0,5,119,3,"n@h",7:32,1:32,2:32,3:32,4:32,4294967295:32>>}
]).
```

All three versions produced identical canonical bytes, added to the provenance
manifest. Tests cover every truncated prefix of a reference, significant bits,
word/byte budgets, allocation-failure cleanup, exact round trips, value equality
and invalid control shapes. Reference words use fixed inline storage; only node
bytes allocate. Pure control parsing accepts PID targets only.

## W4 — Process-monitor negotiation and conformance

Real OTP tests first failed with a PID-only flag: no MONITOR_P arrived and the
monitor observed only connection lifetime. OTP 27 `dist.c` explicitly requires
both DIST_MONITOR and DIST_MONITOR_NAME in its send/demonitor/exit functions.
The corrected profile implements both, including named-target wire shapes,
unknown-name `noproc` and discovery-endpoint lifetime independent of the worker.
The lifecycle ADR and normative source index record the reason for this change.

A pure conformance test compares MONITOR_P framing, NEW_PID_EXT and
NEWER_REFERENCE_EXT against a manually assembled structural vector; it is not
mislabelled as a captured OTP fixture. Actual OTP 25/26/27 monitor tests pass in
Debug and ReleaseSafe; see [runtime evidence](../phase-c/2026-10-25-m1.md).

This does not close the mandatory ETF capability gap: maps, numeric/function/
port/bitstring encodings and other unsupported terms remain restricted. No arbitrary-term or general node compatibility follows from the narrow
send/monitor profile.
