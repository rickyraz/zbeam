# Two-worker CLI integration — 2026-10-28

`serve-workers` adds a separate loopback listener and private two-task service;
`serve-worker` remains M1. The executable uses the existing EPMD registration
loss watcher. This unit enables basic OTP smoke, not final M2b acceptance.

## Verification

Zig 0.17.0 on Linux/WSL, pinned Linux Docker images and separate debug/safe caches:

- `zig build test-interop-docker -Doptimize=<debug|safe> -j2 --summary all`:
  7/7 steps, OTP 25/26/27 all present, zero missing in each mode. Every target
  executes the new two-worker marker in addition to existing M1/MVP smoke.
  Checks cover both identities and exact digests including 1 MiB, bad request,
  stale route, disconnect/reconnect, PID/name monitors, stop and sibling survival.
- `zig build test-all test-labs test-task-lifecycle test-worker-recovery
  -Doptimize=<debug|safe> -j2 --summary all`: 72/72 steps in each mode.
  Debug newly executed 35/36 tests with one skip; safe 122/124 with two skips;
  remaining steps were cached. The separate spin watchdog killed/reaped its
  child; the local example, guardian and M1 recovery campaign passed in both.
  M1 recovery does not prove M2b recovery.
- The first CLI build failed on a runtime-selected `comptime_int`; the typed
  `usize` fix and original log are retained. OTP 29 development smoke and the
  guide example (using unique test node names) also passed.

## Limits and rollback

Independent fixtures, saturation/control ordering, M2b process-loss/no-replay
recovery and actual-master acceptance remain open. The listener uses a private
runtime, one peer, cooperative deadlines and no automatic replay; it is not a
scheduler or production certification. Remove the new service selection, CLI,
smoke script/matrix hook and associated docs to roll back without changing M1.
